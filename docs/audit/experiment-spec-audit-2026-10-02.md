# Experiment Spec Audit — 2026-10-02

Scope: `main` implementation at merge commit 237969ea8b629da12945bc39ccc388bce4d251a2, compared with the original design and `docs/specs/experiment-classic-reference-specs.md`.

Status meanings:
- PASS CORE: defining Classic stimulus is substantially correct, though UI/Lab completeness may still be missing.
- PARTIAL: recognizable mechanism exists, but one or more defining Classic details or required behaviors are wrong/missing.
- FAIL CLASSIC: implementation is not a faithful Classic version of the named illusion.

Global findings

1. No experiment has the per-experiment visualization specified in the design. All experiments share a generic measured-output spectrum/orbit visualization.
2. Response controls are generic across the whole laboratory (Rising, Falling, Ambiguous, One stream, Two streams, Tone heard) instead of changing to the experiment-specific response schema.
3. Lab mode exposes only fields already present in `classicParams`; many required Lab parameters therefore do not exist at all.
4. Several Classic timing structures use `setInterval` plus short tone bursts. This introduces gaps and browser-timer jitter where the canonical stimuli require continuous or sample-stable dichotic presentation.
5. The existing unit tests validate helper mathematics but do not offline-render most named stimuli. A passing CI run therefore does not establish psychoacoustic correctness.

## Per-experiment audit

### 1. Shepard Circular Pitch — PARTIAL

What exists: octave-related oscillator bank and smooth spectral weighting.

Problems:
- Classic stepping is generated by quantizing a global continuous phase, but the entire bank shares a common octave wrap. This can produce a simultaneous octave discontinuity instead of individually hidden component recycling.
- `step size`, waveform and detune from the design are absent.
- Classic `direction` affects frequency formula but the pitch-class scheduler itself is not a true explicit 12-note circular sequence.
- No pitch helix/active-partial visualization.

Root cause: a reusable continuous-frame helper was used as both the discrete Shepard sequence and the Risset glide without a dedicated per-component wrap scheduler.

### 2. Shepard–Risset Glide — PARTIAL / HIGH RISK

What exists: continuously updated octave-spaced bank with spectral weighting.

Problems:
- All component frequencies derive from one shared phase. At phase wrap, the whole bank jumps by an octave together rather than layers independently recycling at opposite spectral edges.
- Stereo spread control absent.
- No scrolling log-frequency verification view.

This can sound like an infinite glide at some settings, but its wrap architecture does not meet the spec for a seamless Risset glide.

### 3. Risset Rhythm — PARTIAL / HIGH RISK

What exists: multiple pulse layers with power-of-two-related rates and cyclic weights.

Problems:
- All layer rates derive from one shared phase and therefore share a common cycle reset.
- `density` exists in Classic parameters but is not used by the runtime.
- Pulse timbre and stereo spread are not implemented as Lab controls.
- Browser `setInterval` scheduling rather than look-ahead/audio-clock scheduling can jitter.

### 4. Octave Illusion — PARTIAL, CLASSIC TIMING WRONG

Correct elements: 400/800 Hz defaults and reciprocal simultaneous L/R assignment.

Problems:
- Canonical state duration is 250 ms at four states/second. Current default uses `rate:4`, but each tone burst lasts only 180 ms, creating ~70 ms amplitude gaps.
- The classic Deutsch construction specifically follows without amplitude drops at state transitions; current bursts fade almost to zero before every transition.
- No physical L/R event-lane visualization or high/low-side response controls.

### 5. Scale Illusion — PARTIAL, REFERENCE RATE WRONG

Correct elements: ascending and descending major-scale lines and reciprocal alternating ear assignment.

Problems:
- Canonical sequence runs four tone positions/second (250 ms). Current Classic default is `tempo:6` (~166.7 ms positions).
- Current bursts last 140 ms, creating additional gaps between positions.
- No historical/reference C-major frequency fixture or explicit continuous repetition test.
- Required high/low stream localization responses are absent.

### 6. Chromatic Illusion — FAIL CLASSIC

Problems:
- Classic reference is a chromatic scale spanning two octaves; current helper creates only 12 semitone positions (one octave).
- Default rate is 6 positions/s rather than the Scale-Illusion-style four positions/s reference convention.
- Same 140 ms burst/gap issue as Scale.
- No one-octave versus two-octave reference choice.

### 7. Cambiata Illusion — FAIL CLASSIC

Problems:
- Runtime generates an invented four-pair sequence around MIDI 69 using ±5/±7 semitone offsets.
- There is no evidence that this is the Deutsch Cambiata event pattern.
- The official illusion depends on a specific repeating pattern whose isolated channels leap in pitch and whose combined tones regroup into two close three-tone melodies.
- No canonical fixture/test exists.

Action required before code changes: transcribe the official Figure 1/reference audio into a committed note/channel event fixture and test against it.

### 8. Tritone Paradox Mapper — PARTIAL

Correct elements: octave-complex tones; six-semitone separation; bell-like weighting.

Problems:
- Runtime endlessly alternates only one root-class pair (`rootClass` and +6), so it is not a mapper across pitch classes.
- No randomized/multi-class trial sequence.
- No local pitch-class response map.
- Response buttons are not bound to trial metadata.

### 9. Glissando Illusion — FAIL CLASSIC

Current runtime:
- uses a fixed triangle oscillator rather than an oboe-like tone;
- sweeps the sine glissando only upward once rather than repeatedly up and down;
- defaults ~300–1200 Hz rather than 131–523 Hz;
- swaps speakers every 500 ms rather than 238 ms;
- defaults to a 6 s one-way glide rather than 2.5 s cycle.

The current implementation is a stereo glide demonstration, not Deutsch's Glissando Illusion.

### 10. Auditory Stream Segregation — PASS CORE / INCOMPLETE FEATURE

Correct core: A-B-A-rest sequence is implemented and repeated.

Problems:
- Only frequency/rate are exposed; timbre, stereo and level differences required by Lab mode are absent.
- No one/two/switching-specific response set (only one/two generic buttons, no Switching).
- No user boundary map.
- `setInterval` timing is not audio-clock scheduled.

### 11. Continuity / Filling-in — FAIL SPEC INVARIANT

Problems:
- Only the masked-gap condition exists; uninterrupted and silent-gap comparison conditions are absent.
- Target is reduced to gain `0.00001`, not physically/digitally absent. The design explicitly requires the target to be absent during the gap.
- Masker bandwidth/type controls are absent.
- Visualization does not separately show zero target during masker.

This directly violates an explicit invariant in the original design.

### 12. Zwicker Phantom Tone — FAIL CLASSIC

Problems:
- A single `BiquadFilterNode` in `notch` mode is used as the inducer. This is a narrow second-order notch, not a controlled broad spectral gap of roughly 0.77–1 octave / ~5–6 ERB.
- Default width is 1000 Hz around 4 kHz, and the Q mapping does not make that an accurately defined 1000 Hz flat/deep spectral notch.
- Noise lower/upper bandwidth and notch depth are not controlled.
- No FFT acceptance test verifies notch width/depth.
- Post-inducer digital silence is not explicitly tested.

This is a likely reason the illusion is weak or absent for users.

### 13. Missing Fundamental — PASS CORE / INCOMPLETE FEATURE

Correct core: generates consecutive integer harmonics beginning at harmonic 2 and does not intentionally synthesize f0.

Problems:
- Phase mode and harmonic-amplitude controls required by Lab mode are absent.
- No offline FFT test verifies the absent f0 in the actual rendered Web Audio output.
- Response UI lacks pitch estimate.

### 14. Combination-Tone Explorer — PASS CORE / INCOMPLETE FEATURE

Correct core: Classic generates only two sine primaries; predicted products are calculated separately and labeled as predicted.

Problems:
- No primary level-balance control.
- No rendered FFT tolerance test proving products are absent digitally.
- No listener product-frequency report.

Core signal construction is among the closest to the intended spec.

### 15. Precedence / Haas Explorer — FAIL CLASSIC

Problems:
- Runtime uses one continuously running 330 Hz sine duplicated into lead and delayed channels.
- Precedence research demonstrations use brief localized events (clicks, noise bursts, tone pips, speech/transients) presented as discrete lead/lag events.
- A sustained sine after its onset primarily creates phase/interference/spatial-width effects and does not repeatedly demonstrate fusion/localization dominance.
- No source-type or ILD controls; no One/Wide/Two plus location response UI.

### 16. Speech-to-Song — PARTIAL / ARCHITECTURE VIOLATION

Correct principle: user audio is recorded and repeated unchanged.

Problems:
- `repetitions` and `interval` Classic parameters are ignored.
- Playback is an `HTMLAudioElement` loop stopped by a 12-second timer, not ten controlled repetitions.
- HTML media playback bypasses the shared AudioEngine safety/master/panic graph; global Panic does not own this playback.
- No Speech/Song-like/Mixed response control.
- Recording is a phrase only; no optional full-sentence→embedded-phrase→sentence demonstration.

### 17. Phantom Words — FAIL CLASSIC

Problems:
- Runtime does not use speech recordings. It extracts a vowel character from the typed text and synthesizes three triangle-wave formant-like tones.
- Consonants, syllable timing, speech envelopes and intelligibility are absent.
- The defining phenomenon uses actual repeated monosyllabic/two-syllable speech sequences offset across loudspeakers.
- Current output therefore cannot faithfully reproduce Deutsch's Phantom Words illusion.
- Free-text left/right percept reporting is absent.

### 18. Mysterious Melody — PASS CORE / PARTIAL FEATURE

Correct core:
- uses a recognizable melody;
- changes notes by whole octaves only, preserving pitch class;
- deterministic seed means repeated Classic starts reuse the same scramble;
- `reveal` decreases scramble depth.

Problems:
- Fixed bundled melody only; no user-entered melody/source selector.
- `reveal` is implemented by reducing random octave-depth rather than providing a clear original-registry reveal/reference condition.
- No Recognized/Not Recognized response controls.
- Rhythm/source metadata are implicit rather than modeled explicitly.

## Recommended implementation strategy

Do not patch all 18 in one large runtime function. Give every experiment an explicit controller/module with its own Classic fixture, validation and offline test. Stereo/timing-heavy experiments should use AudioContext-time scheduling or pre-rendered buffers rather than `setInterval` for defining events. The shared catalog should point to tested controllers, while UI response controls and visualizations should be declared per experiment.
